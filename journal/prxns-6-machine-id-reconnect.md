# PRXNS-6 — реконнект вместо смерти на «machine id rejected»

**Дата:** 2026-07-13 (ночь). **Триггер:** 12.07 у Ильи после сна мака прокси вылетел с ошибкой «Device is bound to a different machine», туннель умер, всё что жило за прокси (включая Claude Desktop) потеряло сеть и разлогинилось.

## Расследование

Логи (`~/Library/Logs/proxyness/daemon.log`) обрываются 11.07 19:14 без единого маркера `machine id rejected` — сам инцидент в лог не попал (лог пишет Electron, а он умер вместе со всем). Зато код рассказал всё сам: цепочка была спроектирована как фатальная.

1. `pkg/machineid`: после пробуждения `ioreg` до нескольких секунд не отдаёт IOPlatformUUID. Ретрай-бюджет 5с; если не успел — демон шлёт fingerprint от строки `"unknown"`.
2. Сервер отвечает `machine id rejected` (в БД лежит настоящий отпечаток).
3. Демон: `reconnectTransport` при этой строке мгновенно выходил из ретрай-цикла; per-stream пути (`proxyTCPTransport`/UDP/legacy) делали `stopLocked` с `lastError = "Device is bound to a different machine"`.
4. Клиент: `isKeyRejected` матчил эту строку → глушил авто-реконнект (sysproxy off, жди ручного Connect). Плюс `startReconnect` в принципе сдавался после 5×5с («Server unavailable»).

Бонус-находка: `stopReconnect` не сбрасывал `reconnectingRef` — отменённый на таймере цикл навсегда блокировал будущие авто-реконнекты до перезапуска приложения.

## Решение — три слоя

- **Корень.** `machineid`: hardware ID мемоизируется в процессе и кэшируется на диск (`~/.config/proxyness/machine-id`). Лестница: живой запрос → дисковый кэш → `"unknown"`. После первого успешного чтения отпечаток деградировать не может.
- **Демон.** `machine id rejected` — ретраябельная ошибка (фатальной осталась только `invalid key`): рестарт сервера ре-биндит отпечаток при следующем коннекте. Per-stream реджект → `machineIDRejected()` закрывает транспорт → D1 пересобирает его штатной лестницей восстановления (зеркало `WakeReconnect`), движок не стопится.
- **Клиент.** `startReconnect` больше не сдаётся: 5 быстрых попыток по 5с, дальше по 30с бесконечно — выход только по успеху, ручному Disconnect или `invalid key`. Классификатор фатальности сузили до `isKeyInvalid`.

## Проверка

`make test` — все Go-тесты зелёные, включая 6 новых на кэш machineid и 2 на `machineIDRejected`. `tsc --noEmit` клиента чистый.
